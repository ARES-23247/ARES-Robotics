## Summary of findings and changes

Following `docs/audits/NEXT_CALIBRATION_WIRE_PROMPT.md`, `docs/audits/TUNING_LEASE_RECOVERY_PEER_REVIEW.md`,
and `docs/audits/LIVE_TUNING_CONSUMER_PEER_REVIEW.md`, this checkpoint eliminates the remaining
in-process topic seam (`NT4Server.publishTopic`) for calibration controls (`SysId/Command`,
`SysId/EnableToken`, `SysId/EnableLease`) in `consumerLiveTuningBehavior`. That scenario's calibration controls come from
`SysIdSignalGenerator` and its controls/typed tuning proposals use `Nt4OutboundPublisher` bytes
parsed by the robot's `NT4Server`. The separate `consumerLeaseRecoveryBehavior` retains the
in-process SysId seam; no claim is made that every scenario has switched to wire replay.

### 1. Loopback unit test (`Nt4TuningRequestWireAuditTest.kt`)
Added `public calibration publisher reaches an owned loopback server with stop token and renewable lease`
verifying that `Nt4OutboundPublisher` paired with `SysIdSignalGenerator` via `CalibrationCommandTransport`:
- Uses the production fixed-topic announcements, including SysId pubuids 1015, 1016 and 1017.
- Encodes binary frames for `SysId/Command` ("STOP"), `SysId/EnableToken` (a generated `ares-` UUID token), and `SysId/EnableLease` (1.0).
- Observes initial lease 1.0 and a second arm with lease 2.0. The submitted loopback test did
  not wait for periodic renewal; the peer review adds controlled renewal and cancellation checks.
- Successfully disarms by revoking `SysId/EnableToken` to `""` and publishing "STOP".
- Delivers all frames across an owned loopback `NT4Server` with correct values received.

### 2. Studio wire fixture capture (`ConsumerTuningWireFixture.kt`)

  * **2520 ms**: Deliver `invalid` (nonce 3L, value -5.0). Rejected with `INVALID_VALUE`.
  * **2540 ms**: Deliver `wire-disarm`. Robot disarms on `ENABLE_TOKEN_CHANGED`, neutralizes during transition frame.
  * **2560–3000 ms**: Manual repositioning resumes; held joystick drives motors (`motors.any { abs(it.power) > 0.01 }`).
  * **3020 ms**: Deliver `disarmed` (nonce 4L, value 3.6). Polling eligible (3020 - 2520 = 500 ms); rejected with `SESSION_NOT_ARMED`.
  * **3040 ms**: Deliver `wire-rearm`. Robot acknowledges fresh STOP session, rearms, and resumes neutral output hold.
  * **3060–3500 ms**: Periodic leases delivered (`wire-lease-10` at 3240 ms, `wire-lease-11` at 3440 ms); neutral output held.
  * **3520 ms**: Deliver `wire-rearm-apply` (nonce 5L, value 3.2). Polling eligible (3520 - 3020 = 500 ms); applied with `APPLIED` ($K_p = 3.2$).
  * **3540–3600 ms**: Normal control restored (`robot.disableCalibrationMode()`). Target heading 0.0, observed heading -0.10 rad (error +0.10 rad), verified angular velocity $\omega = +0.32$ rad/s matching P-only oracle.

## Limitations

- This verification exercises the real generated FTC OpMode runtime and simulated IO.
- Live-tuning calibration controls and tuning requests are produced by the actual Studio publisher
  and replayed into the actual NT4 parser using proxy WebSocket sessions. The capture mocks the
  client connection/capability state and supplies a transport forwarding directly to the publisher;
  robot acknowledgements are not fed back into that capturing Studio instance.
- Gamepad input does not exercise the remote drive-frame lease.
- The separate loopback test does use real WebSocket transport and the public Nt4ClientService,
  but has no generated robot policy. No combined bidirectional Studio/generated-robot socket
  journey, live GUI, physical hardware, or target-controller allocation measurement is claimed.
