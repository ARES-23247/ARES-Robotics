# ARES programming, data analysis, and AI integration audit

November 18, 2026 · Studio 7.0.79 · ARESLib 20.0.6 · Windows, JDK 21

The baseline audit found that project initialization could overwrite team files, generated FTC OpModes failed to compile, and several analysis workflows could report results without supporting telemetry. The repair and verification results follow.

The audit used an isolated checkout of GitHub main at `1df7d0805`. The open working tree was on Studio 7.0.65 with over 1,000 pending status entries. This was a workflow audit of the integrated source. Physical robot behavior, released installer bytes, and live Gemini or Vertex responses were outside the verification performed.

## Repair results

The local repair branch is `codex/studio-environment-repairs`. The findings below describe the original revision. Public publication of ARESLib 20.0.6 and Studio remains pending by request.

## Findings to address first

| Priority | Workflow and evidence | Repair and acceptance check |
|---|---|---|
| P1 | **MCP initialization overwrites existing files.** I placed team instructions in a disposable directory’s `README.md` and initialized an FTC project there. The packaged MCP server returned success and replaced the file. It checks for an existing `.ares` directory, extracts directly into the destination, then takes its optional Git snapshot. [Initialization](https://github.com/ARES-23247/ARES-Robotics/blob/1df7d0805d82081d09119c0dad05ff059d1decaa/ARES-Analytics/mcp/src/main/kotlin/com/ares/analytics/mcp/engine/HeadlessProjectEngine.kt#L158) · [File write](https://github.com/ARES-23247/ARES-Robotics/blob/1df7d0805d82081d09119c0dad05ff059d1decaa/ARES-Analytics/mcp/src/main/kotlin/com/ares/analytics/mcp/engine/ProjectCodegenConventions.kt#L179) | Stage and validate the starter first. Detect destination collisions before writing any files. Test both a pre-existing README and a failed initialization, and verify the team’s original files byte for byte. |
| P1 | **The default Studio build cannot resolve its pinned BOM.** The release-mode build stopped at `:shared:compileKotlin`. The exact `org.aresfirst.ares:ares-bom:20.0.6` POM returned HTTP 404 from Maven Central and from the configured GitHub Maven branch. Gradle also reported DNS failure on its Compose fallback. The FTC and FRC starter archives I extracted both pin 20.0.6. [Release pin](https://github.com/ARES-23247/ARES-Robotics/blob/1df7d0805d82081d09119c0dad05ff059d1decaa/release/ares-versions.properties#L5) · [Repositories](https://github.com/ARES-23247/ARES-Robotics/blob/1df7d0805d82081d09119c0dad05ff059d1decaa/ARES-Analytics/settings.gradle.kts#L20) | Reconcile the pin with the approved publication, then verify Studio and an exported FTC and FRC starter against the public artifacts in a fresh dependency cache. |
| P1 | **Generated FTC OpModes fail SDK compilation.** I requested a TeleOp from MCP and compiled the returned Kotlin against RobotCore 12.0.0. Kotlin rejected `fun stop()` at generated line 48. The inherited `LinearOpMode.stop()` is final. Autonomous uses the same renderer. The generated unit-test scaffold also implements a test-local control loop. In a `LiftTest` preview, the production subject appeared only in a comment and the test class name. [OpMode renderer](https://github.com/ARES-23247/ARES-Robotics/blob/1df7d0805d82081d09119c0dad05ff059d1decaa/ARES-Analytics/mcp/src/main/kotlin/com/ares/analytics/mcp/scaffold/FtcKotlinScaffoldRenderer.kt#L218) · [Test renderer](https://github.com/ARES-23247/ARES-Robotics/blob/1df7d0805d82081d09119c0dad05ff059d1decaa/ARES-Analytics/mcp/src/main/kotlin/com/ares/analytics/mcp/scaffold/MockIoTestScaffoldRenderer.kt#L32) | Rename the generated cleanup helper, call it through the lifecycle paths, and compile both scaffold types against the pinned SDK. Generate a test that invokes the actual adapter and fails if its neutral-output behavior regresses. |
| P1 | **Cohort statistics count missing telemetry as measured zero.** I passed a session summary with identity fields only to the compiled analyzer. Cross-track error, EKF drift, vision acceptance and vision latency each returned one sample with median zero. The producer encodes absent scalar metrics as zero. A cohort with fewer sensors can therefore appear to track more accurately or have lower latency. [Missing-value fallback](https://github.com/ARES-23247/ARES-Robotics/blob/1df7d0805d82081d09119c0dad05ff059d1decaa/ARES-Analytics/app/src/main/kotlin/com/ares/analytics/service/SummaryMetricAggregator.kt#L11) · [Cohort extraction](https://github.com/ARES-23247/ARES-Robotics/blob/1df7d0805d82081d09119c0dad05ff059d1decaa/ARES-Analytics/app/src/main/kotlin/com/ares/analytics/domain/analysis/CohortStatisticsAnalyzer.kt#L60) | Carry metric availability or sample counts through storage and analysis. Preserve genuine zero measurements. Display how many runs supplied each metric and test a cohort containing both missing and measured zeros. |
| P1 | **An invalid battery-resistance fit earns a GOOD grade.** Ten synchronized samples with current rising from 0 to 9 A and voltage rising from 12.00 to 12.18 V produced a positive 0.020 V/A slope. The compiled analyzer reported 0.0 mΩ and GOOD. The dashboard also falls back to the first and last available topics when a battery channel is missing. [Fit and grade](https://github.com/ARES-23247/ARES-Robotics/blob/1df7d0805d82081d09119c0dad05ff059d1decaa/ARES-Analytics/app/src/main/kotlin/com/ares/analytics/service/analysis/ScatterRegressionAnalyzer.kt#L169) · [Channel selection](https://github.com/ARES-23247/ARES-Robotics/blob/1df7d0805d82081d09119c0dad05ff059d1decaa/ARES-Analytics/app/src/main/kotlin/com/ares/analytics/ui/components/dashboard/analysis/XyScatterWidget.kt#L49) | Require suitable current and voltage channels and a fit consistent with battery sag before showing a grade. Display “Insufficient evidence” with the reason. Test reversed slope, unrelated channels, steady voltage, and a known valid fit. |
| P1 | **The SQL Analyst can answer for another workspace.** Source tracing shows Run History loads sessions for one team, season and robot, but passes only the question to the analyst. The analyst executes generated SQL against the shared desktop database, then sends the returned rows to the configured provider. An ordinary average can mix robots on a shared laptop.
